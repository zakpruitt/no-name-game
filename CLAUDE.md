# Awaken

Fast-paced 3D combo hack and slash. Godot 4.7, GDScript. Original characters only (no licensed IP in the repo).

For now the game is just the heretic's combat in a training room (ROADMAP round 28): no run, rooms, rewards or title screen. It boots straight into training.

## Design pillars
1. **Combat feel first.** Light / right-click strings, dash cancels out of anything,
   hitstop + shake + knockback + flash on every hit. Tune before adding content.
2. **Combos are the game.** Every string has a name, a guide row and (for the enders) a timed breaker;
   the weapon a light forms decides what the tentacle's right click does.
3. **Awakening.** Style rank (variety > mashing) fills the meter; activating it powers the hero up
   (damage, armour, gold rim, charged axe) with a cinematic burst.
4. **Chibi but badass** (`docs/features/art-direction.md`), in the comic style.

## Layout
- `scripts/game.gd` — autoload `Game`: hitstop, shake, combo/style rank, Awakening meter, input map (bound in code). Hitstop has a shape (`HITSTOP_EASE`/`SLOWMO_EASE` eased tail, `HITSTOP_OPENER` snappier first hit, breaker focus flat, overlapping stops each keep theirs: `_stops`, `_update_hitstop()`), raises `hit_weight` (the weapon trail swells with it) and fires the comic impact frame (`scripts/impact_frame.gd`, `Game.impact`: a screen-reading CanvasLayer under the HUD, big stops and kills, `reduce_flashing` keeps only a vignette pulse). Checks: `tests/hitstop_check.gd`, `tests/impact_frame_check.gd` (PASS/FAIL); look: `godot --path . -s tests/impact_preview.gd` → `user://impact_preview.png`. See `docs/features/impact-feedback.md`
- `scripts/player.gd` — the heretic: node, signals, exports, every field of his state, `_ready`, the `_physics_process` dispatch and the MOVE / ATTACK / DASH / HURT / CHARGE states, hits (`_do_hit`) and `take_hit`. The work is split by job into static-function files over that state (the `void_element.gd` pattern); other scripts and the checks call them directly on the hero's preloads (`hero.HERO_INPUT.cancel_point(hero)`, `HERO_MOVES.void_route()`, ...). player.gd keeps `breaker_window()` (breaker_prompt's test fakes duck-type it), four forwarders for files another lane owns (`_cast_power()`, `_cast_grow()`, `cancel_point()`, `combo_window()`) and re-exports `MOVES`, `COMBOS`, `GUIDE_LEARNED`, `BUFFER_MS`, `BREAKER_SPILL` / `BREAKER_EARLY`, `COMBO_TIER_COLORS` / `COMBO_TIER_SFX` / `COMBO_SFX_DB`:
  - `scripts/hero_moves.gd` — `MOVES` (timings are fractions of anim length; string pacing `L1_SPEED` / `L3_SPEED` / `EM_SPEED`; numbers: `tests/rhythm_check.gd`), `COMBOS` (name, input, tier: landing one plays `combo_<tier>` and shows the name above him), `MOVE_NAMES`. `void_route()` is the only routing function (`routed()` adds the frost-spear vault; `player._next_move()`, the combo guide and the checks all use it). Hops / air moves / air dash / plunge (`hop()`, `air_home()`, `air_dash_cut()`; see `docs/features/combo-breakers.md`), `progress()`, `effective_move()`, the guide's rows (`combo_options()`)

  - `scripts/hero_leap.gd` — State.LEAP, the combo breaker leap / window / press / dive / impact driven by `VOID_ELEMENT.BREAKERS` (`BREAKER_*`, `window()` for the prompt)
  - `scripts/hero_awaken.gd` — Awakening on the hero: activation burst, the buff (`ANIM_MULT`, `DAMAGE_MULT`, `DAMAGE_TAKEN`, gold `AWAKEN_COLOR`), the drain
  - `scripts/hero_fx.gd` — the hero's look on a hit: `swoosh()`, the combo-name callout (`combo_callout()`), the ender camera kick (`camera_hit()`, `ENDER_ZOOM`), the rank-up and last-kill bursts (`LAST_KILL_SLOWMO`). `cast()` fires the spirit casts (`elements.CASTS`: echo on L1 / L2, the claw's inked lash on DL, `scripts/claw_lash.gd`; `docs/features/spirit-casts.md`). The hero's own element is spirit (`element()`); each void move takes its element from the weapon (`VOID_ELEMENT.ELEMENT_OF`)
- `scripts/kit_slots.gd` — the kit grammar's slot table as data (`KitSlots`: `GROUPS`, `SLOTS`, the heretic's card `HERETIC`: slot -> move id + input, route steps, demoted upgrades; `of(Game.hero)`, `open()` for the routing gate, `tag_of()` for the guide). ## Workflow
- **Several agents at once:** each agent works in its own git worktree and branch (`bash tools/agent.sh new <name>` → `../awaken-<name>`, branch `agent/<name>`), commits there, and lands with `bash tools/agent.sh land` (rebase onto dev, resolve your own conflicts, headless checks, fast-forward dev). Never stage or commit in another agent's checkout, including `awaken/`. Rules: `docs/agents.md`
- VS Code: `.vscode/` recommends godot-tools (keep the Godot editor open for its language server and debugger), has launch configs (Play (training room), windowed Autotest, Current scene) and tasks for the headless checks (`Checks: all` is the default test task, `Check: one test` picks one)
- All checks: `bash tools/agent.sh check` (the PASS/FAIL tests in its list, then the autotest twice, plain and with `--kit=full`, each asserting `[kit] slots=N/N windows=N/N`; `--quick` skips the tests). Tests: `void_arm_check`, `guide_check`, `training_check`, `prompt_follow_check`, `move_list_check`, `comic_check`, `hitstop_check`, `camera_feel_check`, `impact_frame_check`, `trail_check`, `rhythm_check` (retried once on a FAIL: it can miss by a frame under load), `fx_free_check`, `foe_stride_check`, `hero_stride_check`, `fx_sleek_check`, `lean_spike_check`, `prince_check`, `ice_block_check`, `counter_check`, `kit_check`, `lava_leash_check`, `input_snap_check` (round 51: a press at every ms through every route step, dash cancel and breaker window lands the documented move) (run one: `godot --headless --path . -s tests/<name>.gd`); also `tests/enemy_feel_check.gd`
- Autotest (compile + a bot playing every `BOT_STRINGS` string once on the dummies, every breaker, about 31 s: it runs past `AUTOTEST_TIME` until `strings=N/N`): `godot --headless --path . -- --autotest`. At the end it prints `[autotest] combo_breaker #N <id> perfect=` per breaker, a `[rhythm]` line per string (ms between move starts and first hit to first hit) and `[autotest] done ... casts= breakers=N/N perfect_breakers= strings=N/N moves=` (every string starts from the same spots, `training_bot.BOT_SPOT`, so the run is repeatable and `agent.sh check` fails unless every breaker and string landed), plus `[training]` and `[perf]` lines (bot lines are buffered: a print mid-fight is a frame spike). `--start-awakened` starts with a full meter, `--reduce-flashing` turns that setting on without saving
- **Perf:** measure windowed. The wall `avg` sits at ~16.5 ms because this machine caps at 60 fps even with vsync off (an empty project measures 16.67 ms); read `cpu avg/worst`, `cpu_spikes` (node work + render submit) and `gpu`. Spike lines name the move and the pipeline compile counts. New effects: no `bake_mesh_from_current_skeleton_pose` per frame, no `print` in play, and rerun `--collect-shaders` so warmup.gd holds their materials' shaders
- Visual check (windowed; screenshots to `%APPDATA%/Godot/app_userdata/Awaken/autotest_*.png`: `autotest_hit.png` ~0.2 s after the first big hit, `autotest_dash.png`, `autotest_guide.png`, `autotest_cast.png`): `godot --path . -- --autotest`. Measure perf windowed, not headless
- Looks (windowed, to `user://`): `tests/element_shots.gd` (every void move and breaker, `-- --only=maw` for one), `tests/heretic_shots.gd` (his rig and weapon changes; PASS/FAIL headless), `tests/comic_shots.gd` / `comic_preview.gd`, `tests/fx_preview.gd [-- --at=0.06 | --swoosh | --death | --dash | --awaken | --shots]`, `tests/trail_preview.gd [-- --swell]`, `tests/impact_preview.gd`, `tests/enemy_feel_preview.gd [-- --bag]`, `tests/breaker_prompt_preview.gd`, `tests/telegraph_preview.gd`, `tests/occlusion_check.gd`, `tests/enemy_lineup.gd`. `user://` is shared by every worktree: copy screenshots out right away
- Film (windowed): `tests/string_film.gd` plays every `BOT_STRINGS` string with the bot and films it at 12 fps from the game camera, plus a HIT frame after each hit, to `user://string_film/<string>/NNN.png` + INDEX.txt (real ms, move, time scale), then 10 s of free play (`-- --dir=<name>` its own folder, `--from=N` / `--to=N` a range of strings, `--spar=<kind>` with a live foe); the last audit from it is `docs/feel-audit-2026-11-06b.md` (feel audit 4; earlier `docs/feel-audit-2026-11-06.md`, `-11-05`, `-11-04`), coverage per HIT frame from `python tests/fx_coverage.py <film> --per-string`
- Dead code: `python tools/dead_refs.py [--docs]` lists functions / consts / vars nothing uses; delete by hand, then the autotest's `[improv]`, `strings=` and `breakers=` lines must match
- After adding assets **or a new `class_name`**: `godot --headless --import --path .` (registers global classes)
- Skills in `.claude/skills/`: `roadmap-item` (one change end to end: build, verify, ROADMAP, commit), `combo-feel` (strings that move: MOVES / hops / routing), `combo-breaker` (timed finishers on enders), `spirit-cast` (shaped spectral spells)
- **Engine API reference:** `docs/engine_api/<ClassName>.xml` is the class reference for the exact Godot in use (`VERSION`; also `@GDScript.xml`, `@GlobalScope.xml`). Before using an engine method, property, signal or enum you aren't certain of in 4.7, grep it there (e.g. `method name="look_at"` in `Node3D.xml`, or search all files for a name) rather than recalling it. Regenerate after upgrading Godot: `python tools/gen_engine_api.py`
- **Feature docs:** `docs/features/` has a technical write-up per feature (how it works, files, invariants, tuning, tests); see its README for the index and the template. Read the relevant one before changing a feature, and add or update one in the same commit when you build or change a feature
- Scenes are mostly built in code; keep `.tscn` files minimal unless the user wants editor-authored scenes.
- KayKit models face +Z; facing yaw = `atan2(dir.x, dir.z)`. Characters share one rig, so any KayKit animation works on any character.
- Comic style: copy enemy GLBs with `python tools/comic_glb.py [src] [names]` (a plain copy loses the `g` attribute) and dungeon pieces with `--env`, then `--import`. Check: `godot --headless --path . -s tests/comic_check.gd` (PASS/FAIL: clips after mapping, tones, dungeon set, fallback, text logic, the hero's Ab_ retiming)
- Camera flags (`docs/features/camera.md`): `--cam-dist=N` (metres, default 13), `--cam-fov=N` (degrees, 37), `--cam-frame=N` (most the fight framing zooms out, 1.25; 1 = off), parsed in `camera_rig.cam_overrides()`
- Training flags (`docs/features/training.md`): `--swing` (or Settings "Dummies swing") has the dummies swing at him so the dash counter can be practised; `--spar=minion|rogue|shield|warrior` adds one live foe at 1/3 damage (`scripts/spar.gd`; the autotest prints `[spar] type= hits_taken= kills=`); `--bag-damping=N`, `--bag-stiffness=N`, `--bag-lean=N`, `--bag-squash=N` hand-tune the dummies' punching-bag spring live (`training_dummy.bag_overrides`). Each dummy shows a `LAST n` tag of its last string's damage. Element slams that crater (Deep Freeze, Meteor Fall, Maw) pass `Vector3.DOWN * *_DOWN` as knockback; the Warden reacts with `boss._boss_reaction` (flash, and ink + small squash on big hits)
- **Wiki** (`docs/wiki/`, the player-facing field guide, published to https://zakpruitt.github.io/no-name-game/ by `.github/workflows/wiki.yml` when a push to dev touches it): `python tools/wiki.py` rebuilds `docs/wiki/data.js` from the code (`tools/wiki_data.gd`: the kit card, the moves, BREAKERS with their words, the rules, the counter) and says which ids `docs/wiki/notes.js` (hand-written states and best situations) lacks; `tests/wiki_check.gd` (in `agent.sh check`) fails when data.js is stale, so a lane that changes a move, slot, breaker or rule reruns `python tools/wiki.py` and commits data.js. Screenshots in `docs/wiki/img/` are cropped jpgs from `string_film.gd -- --dir=wiki_film`, `heretic_shots.gd`. See `docs/features/wiki.md`
