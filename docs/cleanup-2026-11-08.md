# Cleanup, 2026-11-08: the code review and the cut

Zak asked for a harsh pass over the code before the next phase: evaluate how idiomatic, redundant and
optimised it is, cut what is not needed for the combos to work, explain the structure (now
`docs/architecture.md`), and bring the agent harness up to date. This is what was found and what changed.
The audit reports themselves were written against `dev` at `f44cf1b`; this branch landed after the fx-queue
lanes (`fe95139`).

## What the review found

The code was written by many lanes over four days. The core (`player.gd`, `hero_*.gd`, `game.gd`,
`hero_input.gd`) is typed and well shaped: a node holds the state, static-function files hold the logic by
subject, and tuning lives in tables. The problems were around it:

1. **Two flags that were constants.** `Game.comic_style` was `var comic_style := true` and never assigned;
   `designed_fx.on()` was false only with `--fx=classic`, which no test, check or autotest ever passed. Every
   `else` behind them (the old runtime polygon effects, the KayKit fallbacks) was unreachable in play *and*
   untested: about 5,000 lines across 60 files.
2. **Code only tests could reach.** The dragon prince slice (`--hero=prince`, 1,254 lines), the Bone Warden
   boss, necromancer and bomber (never spawned; `main._spawn_boss` existed for a test), elite and volatile
   foes, the heavy-target tentacle pull (no foe in play is heavy).
3. **The same thing written many times.** 17 copies of "living foes within r, not flying, sorted by flat
   distance" in `void_element.gd` alone (23 sort lambdas), 85 `take_hit` + `register_hit` pairs, ~30 flat-vector
   helpers, 6 prewarm routines, 5 sheet-registry formats, 12 MeshInstance3D builders, the per-foe tentacle
   choreography state machine 8 times.
4. **Changelog comments.** Hundreds of comments of the form "round 51 (was 1.2, then 1.5): ..." that record
   history instead of saying what the code does; CLAUDE.md had become 38 KB of the same.
5. **Per-frame waste.** `void_element.entry()` rebuilt a merged dictionary every physics frame of every attack;
   the environment scripts `load()`-ed each other 49 times per frame because of a preload cycle;
   `main._fade_occluders` ran `find_children` per occluder per frame; camera `_best_lean` made ~3,600 small
   allocations a frame in a breaker scene; `load()` in hit paths and once per 20 ms of a dive.
6. **One real bug.** `player._is_last_kill()` read a `_queue` field main.gd no longer has, so the last-kill
   slow motion could never fire.
7. **Tests and harness.** 12 stale one-off films and previews; the stand-in `Foe` harness pasted into 8 tests;
   `agents.md` lessons repeated up to nine times (heredocs, CRLF, land races); skills with stale references
   (`player.MOVES`, `main.BOT_STRINGS`, "commit on dev", "first unchecked item" pointing at a deleted system).

The full reports (one per file group, with line numbers) are in the session scratchpad; their conclusions are
folded into this file and `docs/architecture.md`.

## What was consolidated or fixed (behaviour unchanged)

- `scripts/foes.gd` is the one home for foe queries: `near`, `nearest`, `sorted_near`, `sorted_from`, `densest`,
  `alive`, `live`, `flying`, `flat`, `to_flat`, and `hit(e, dmg, kb, launch, big, tag, air)` (take_hit +
  register_hit). 17 sort-and-slice copies, 5 nearest loops, 2 densest loops and 40 hit pairs in `void_element.gd`,
  `void_grab.gd`, `thrown_foe.gd`, `hero_input.gd`, `counter.gd` and `player._do_hit` now call it.
  `_breaker_damage()` replaces 19 copies of the damage formula.
- `void_element.entry()` caches the merged breaker rows (`static var _entries`); writers duplicate.
- `mark()` / `marked()` use prebuilt StringNames instead of building a string per hit.
- The environment preload cycle is broken: `env_target` / `env_piece` / `env_flourish` / `rooms` / `frost_wall`
  use `preload` where safe and one `static var` accessor where a preload would close the cycle; zero `load()`s per
  frame. `env_target.context()` only runs for the moves that can pick a structure.
- `camera_rig`: the viewport rect and tangents are computed once per frame (`_lens()`), the per-point array is two
  scalar `_fit()` calls, the fight framing reuses its arrays, the target's fields are read through StringName
  constants. All numbers unchanged (`camera_feel_check`).
- `main._fade_occluders` caches each occluder's meshes; `impact_frame` preloads the palette; `weapon_trail` caches the
  player; `void_tendril` caches the headless test; `hero_leap._comet` and 8 `load()`s in hit paths are preloads
  or once-fetched statics.
- `designed_breaker.after_beat` registers its smoke with `STANDING` so it fades like every other standing effect
  (it never did). `player._is_last_kill()` is `enemies group empty`.
- `counter_fx`'s two literal register / prewarm pairs are one table. `thrown_foe.clear_from` builds its exclude list
  once per cast.
- Comments: the 50-line pacing changelog in `hero_moves.gd` is one line per constant, the numbers in
  `docs/features/combo-breakers.md` "String pacing history"; every function touched had its changelog comment
  rewritten to what it does.

## Left alone on purpose (your call, Zak)

- **The wiki** (`docs/wiki/`, `tools/wiki.py`, `wiki_check` in the gate). It is a published player guide, not
  combat code; it taxes every lane that changes a constant. Kept and regenerated; drop it if the game stays a
  training room for a while.
- **Three heretic models** (`chibi` default, `v3`, round-28 `heretic`) and both body builders. The v3-vs-chibi
  decision is still open in the roadmap.
- **`--kit=full`**: Storm Pitch and the 18 IMPROV upgrade cells (~270 lines) exist only for the second autotest run
  today; the demo presets use the full kit. Promote them into the base kit or move them to a kit-only file.
- **Perfect dodge vs the counter**: `_start_dash` tries the counter first, so the perfect dodge only fires when a
  dash misses the counter arc. Two systems for one input.
- **Rooms, pieces, flourishes** (~3,000 lines): kept as the heretic's environmental verbs. Dropping them is a
  10-step job listed in the enemies/environment audit.
- **The `comic_*` drawers that still draw polygons** (`comic_fist`, `comic_fault`, `comic_melt`, `comic_steam`,
  `comic_backdraft`'s haul, `comic_improv`'s remaining cells) and the tentacle-choreography scripts: real code,
  but the same shapes written several ways; a shared `FoeChoreo` base and a `FlatMesh.commit` helper are the next
  consolidation.
- **`designed_breaker.Screen._process`** still scans the enemies group every frame for wall splats; a splat counter
  in `thrown_foe` would let it skip. **`Fx.flare`** still draws a non-comic sprite (perfect dodge, projectiles).
- **Tests**: the stand-in `Foe` harness is still pasted into 8 tests; `cool_pass` / `cool3` / `cool4` /
  `env_breaker` / `lava_leash` are one subject in five boots; `agent.sh check` runs serially (~15 min; parallel
  would be ~5). Next harness round.
- Unused textures in `assets/vfx/` (`star_06`, `smoke_04`, `scorch_02`, `spark_05`, `noise_soft`) and the orphaned
  Barbarian texture.
- The `.import` noise: the lanes' files all end CRLF but a few edited today are LF (`git diff` is clean because of
  autocrlf); harmless.
